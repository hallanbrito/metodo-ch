# W Slices

A **W Slice (Work Slice)** is the smallest change capable of delivering verifiable learning or value without breaking product coherence.

It may concern documentation, architecture, functionality, fixes, or experiments. Its size is determined by **review capacity**, not the agent's maximum ability.

## A W Slice ready for execution records

- identifier, objective, and expected value;
- source-of-truth baseline;
- explicitly included and excluded scope;
- approved decisions and decisions that are still prohibited;
- authorized files, components, tools, and access;
- acceptance criteria and required checks;
- autonomy level and accountable human;
- rollback or recovery strategy;
- Evidence Package format.

> **Golden rule of the W Slice:** if the delivery cannot be reviewed with sufficient understanding, the slice is still too large.

## Definition of Ready

A W Slice is ready when purpose and value are understood, baseline confirmed, necessary decisions approved, scope and exclusions recorded, verifiable criteria defined, autonomy established, and conflicts evaluated.

## Definition of Done

A W Slice is done when changes remain in scope, the Evidence Package is complete, applicable tests and checks pass, documentation is consistent, limitations are declared, the human accepts the result, integration is complete, and relevant lessons return to versioned memory.

An agent saying “finished” **does not change the W Slice state**. Completion is a verifiable property of the product and the process.
